# 功能与使用细节

日常使用先看仓库首页。本文保留各渠道的能力范围、修改捕获规则和具体配置。

## 界面语言

支持简体中文和英文，跟随 JetBrains IDE 的界面语言；非中文语言统一使用英文。切换 IDE 语言并重启后生效，聊天设置、ChangeList、Diff 注释面板与原生操作提示同步切换。AI Diff 注释使用界面语言；聊天回复仍遵循用户输入和自定义指令。用户消息、代码、路径和已保存提示词不自动翻译，旧历史中的中文工具记录仍可正常展示与识别。

## 核心能力

### 会话与输入

- 支持 Codex 会话创建、恢复、历史浏览、流式响应和中断；插件历史读取同一 `CODEX_HOME` 下本机各客户端的未归档会话，跨项目完整分页加载，并显示会话工作目录。
- 插件点击已打开的历史会话会定位原页签，运行中的回合继续输出；其他客户端持有写入权时可查看已保存的历史快照，并显示只读提示。原客户端释放会话后点击“重新打开”即可重试恢复；只读期间保留输入草稿，不能发送、重命名、压缩或回溯会话。
- 支持 Claude Code CLI 会话创建、续接、流式响应和工具状态展示。
- GPT 与 Claude 渠道按页签隔离；切换渠道时会在当前页签开启对应的新会话。
- 多个页签可以同时运行独立 AI 回合，后台流式输出不会污染当前页签。
- Codex 首轮成功回复后，插件使用当前 GPT 供应商和模型发起一次临时标题请求，概括对话任务并保存为会话名称，同步到历史列表和对应页签；标题请求不加入聊天记录。手动改名优先，后台生成不会切换页面或覆盖草稿。没有名称的旧历史在继续对话后也会生成标题。
- 输入框支持文本、图片、编辑器选区、项目树拖拽文件和 `@` 文件搜索。
- 首次发送等待 Codex CLI 连接就绪后启动回合；迟到或重复的“已连接”通知不会作废正在运行的回合，首条回复与后续消息保持同一会话绑定。
- 开启“文件上下文”后，可直接选中 ChangeList 的 VCS Diff 或 CodeDeck 修改 Diff 中的代码，再切回输入框提问。支持左右并排和统一视图，附带真实文件路径、原文件行号及选区原文；`before` 表示变更前，`after` 表示变更后。统一视图跨越两个版本时会分别附带选区，输入栏同步显示版本与行号。
- 文件引用以稳定标签插入输入框，可选择、删除、拖动排序、撤销重做；标签与文字混合复制时也可完整粘贴回输入框。
- Codex 发送文件引用时，会在原引用位置把绝对路径写入模型可见的文本；普通发送、排队发送和立即引导共用此处理，文件附件也提供明确路径，图片继续使用原生图片输入。恢复历史时保留新文本引用及旧 `mention` 的标签显示。路径引用供 AI 按需读取文件，不会预先读取整份文件并塞入上下文。
- AI 回复进行中仍可继续发送消息；普通发送会排队，GPT 渠道还支持对当前回合立即引导。

### 供应商与模型

- 内置 Codex 与 Claude Code 的本机 CLI 配置。
- 支持按 GPT / Claude 渠道添加、编辑、启用和删除自定义供应商。
- GPT 自定义供应商支持 Responses API 或 Chat Completions API。
- Claude 自定义供应商通过 `ANTHROPIC_BASE_URL` 与 `ANTHROPIC_AUTH_TOKEN` 接入。
- 启用自定义供应商前会读取模型目录；模型选择器支持添加接口未返回的自定义模型 ID。
- API 密钥和认证令牌保存到 JetBrains PasswordSafe，不写入插件 XML 或网页层状态。

### 修改捕获与 Diff

- Codex 使用 app-server 报告的结构化文件事件，并在命令开始通知到达时，为命令中明确出现的工作区文件路径保存磁盘基线；命令结束时将实际新增、修改和删除加入修改列表，支持 PowerShell `WriteAllText`、`Set-Content`、`Remove-Item` 等场景，不扫描整个工作区。命令工作目录参与相对路径解析。
- 结构化文件事件兼容字符串与对象形式的变更类型；新增、删除事件中的完整文件内容与普通修改的 unified diff 分别处理，空文件也可识别。只有已完成的文件操作进入列表；重新打开历史时可从保存的文件事件恢复新增、删除及仍与当前内容匹配的修改，新增文件撤销会删除文件。
- 补丁移动同时记录源和目标路径，目标已存在时保留其原内容；新建 Codex 会话启用当前 CLI 的实验性原始工具事件，在工具执行前解析字面量补丁路径并保存基线，支持直接 `apply_patch` 与 Code Mode 包装。失败且未改动的预留基线会清除。历史或 CLI 未提供工具前事件时，无法判断移动目标是否覆盖过原文件，该目标仍显示在列表中，但禁止根据猜测的内容撤销。
- PowerShell `Rename-Item` 与 cmd `ren` 的相对新文件名按源文件父目录解析，兼容嵌套引号、中文和空格。命令明确指定的子目录、外部 Node/Python/PowerShell 等脚本的所在子目录会保存有界快照，支持这些目录内的路径拼接、递归复制和删除、新建无扩展名文件。
- 原始 shell 工具调用与结构化 `commandActions` 均参与实时捕获。Git 按提交元数据识别单提交 revert 的受影响路径；发送回合前还按 IDE 的仓库映射，为 HEAD 提交路径和小仓库的索引路径准备有界基线，避免快速 revert 先完成、开始事件后到达时丢失原内容。不遍历工作区查找仓库，排除 `.git`、`.hg`、`.svn` 内部数据库；无法准备的超限仓库路径仍依赖实时事件。
- 命令捕获保留本会话首次未接受的修改前内容，撤销删除会恢复原文件及其 BOM、换行格式；只读命令不会把未变化的文件加入列表。每个文件最多 5 MiB，同一会话待完成命令的快照总计最多 16 MiB；每个命令最多保存 128 个文件，目录枚举最多 512 个条目、16 层，不枚举工作区根目录，不跟随符号链接。超出限制、脚本写入未明确指定的其他目录等情况仍不保证捕获；同一被快照目录中同时发生的用户修改也可能被计入。此补充机制依赖实时命令开始通知，无法为旧历史补录已经丢失的命令基线。
- Claude Code 对 `Write`、`Edit` 和 `NotebookEdit` 文件工具建立首次修改基线。
- “设置 → 基础配置 → 行为 → 保持已有文件换行”默认开启。对具有修改前快照的实时 Codex 补丁 / 命令，以及 Claude 文件工具，在操作或回合结束后保持原有统一 LF / CRLF 和 UTF-8 BOM，代码改动保留。需要主动转换格式时先关闭。新增文件、原本混合换行、无原换行可判断、二进制、非 UTF-8、超限文件和正在手动编辑的未保存文档不自动转换；历史加载不会触发写盘。这是完成后的格式兜底，不能保证外部工具运行期间每一瞬间的文件格式。
- 单项和全部撤销通过 VFS 恢复原始字节并重新加载已打开文档，避免 Windows CRLF 触发编辑器换行断言，同时保留原始 BOM 和混合换行。
- Git / P4 的 revert、restore、reset、checkout、sync 恢复命令跳过自动换行保护，保留版本控制输出的字节；撤销可写回或删除已变为只读的工作文件，未变化文件不会被解锁。对话撤销只恢复工作文件，不撤销 Git 提交、索引或 P4 changelist 状态。没有明确路径的 P4 命令仍不保证捕获，旧历史中丢失的 shell 基线也不能据此补回。
- 修改列表按会话页签隔离，显示新增、修改、删除和行数变化。
- 可以逐个文件接受或撤销修改；新文件撤销时会删除，超过 5 MiB 的文件会标记为不可撤销。
- 从修改列表打开 Diff 时，右侧绑定当前真实源文件；重复打开同一文件会定位到已有 Diff 页签。
- 本地文件路径链接（包括 `file://` URI）支持跳转到 JetBrains 编辑器，也可右键在系统文件管理器中定位。

### 内置 ChangeList

- 打开 **View → Tool Windows → CodeDeck Changes**。按 Changelist、目录、文件展示当前项目中的新增、修改、删除与移动；支持 Git、Perforce 及 IDE 已配置的其他 VCS。
- 可以将 ChangeList 的文件和目录直接拖入 CodeDeck 聊天输入框，按落点插入引用，无需先定位到 Project；目录引用保留目录自身路径，不展开为子文件。ChangeList 使用聊天专用拖拽格式，中间代码区不接收，不会打开文件或插入路径文字；输入框仍接收 Project View 和系统文件拖放。拖拽使用复制语义，已删除文件仍可引用其原路径，图片沿用附件行为，变更分组节点不可拖拽。
- 复用 IDE 的连接与登录。保留文件 / 目录菜单、迁出、取消迁出、撤销修改、定位、复制路径、忽略规则与 Unreal / Unity / C++ / VisualStudio 忽略模板；Perforce 扩展在原生 Perforce 插件启用时加载。
- 在文件或目录的右键菜单中点击“在项目窗口中定位”，会自动打开并切换到 Project 工具窗口，选中目标并移入焦点。
- 变更树只展示当前项目范围。自动刷新和 Perforce 补充扫描默认关闭，按需手动刷新；配置统一位于 **Settings → Tools → CodeDeck → ChangeList**。
- 双击文件打开可复用的原生 Diff。顶部提供“AI 注释”“重新生成”，每个文件独立保存运行状态；切换到其他 Diff 文件可继续并行生成，切回时恢复对应任务与结果。任务运行时显示“停止注释”，只停止此文件所属任务，不影响其他 Diff；此文件由批量队列处理时停止所属队列。完整解释显示在对应代码块下方，VCS Diff 与 CodeDeck 的 AI 修改 Diff 共用这一入口；注释随编辑器可见宽度自动换行，重新打开或缩放 Diff 时会重新排版并铺满可用行宽。
- 注释直接显示标题与正文，不添加“AI ·”前缀；文字为只读文本，支持鼠标拖动选择、`Ctrl+C`、全选，以及右键“复制 / 复制全部”。选择和复制注释不会选中或修改源代码。只修改紧邻声明前的源码注释时，会把说明放到属性 / 宏及完整声明之后，避免拆散注释与函数；独立注释和无法可靠判断范围的函数体保留原落点。
- AI 注释在代码行间占用独立的块空间，窗口变窄、字体缩放或重新打开 Diff 后会更新换行和占位。刷新、重新生成、代码过期或关闭 Diff 时会同时释放旧占位及文本控件，已经失效的占位也会清理，避免残留说明覆盖源码；水平滚动时跟随可见区域，折叠后隐藏。
- AI 注释沿用 CodeDeck 当前的 **GPT 供应商和 Codex CLI 路径**，包括自定义 GPT 供应商。**单文件 Diff 注释、ChangeList 批量注释和聊天各自保存模型、思考程度与 Fast**，互不覆盖；单文件注释配置在各个 Diff 之间复用，模型选择按供应商分别记忆，重新打开窗口或重启 IDE 后保留。升级时为两种注释场景各复制一次原有设置，之后不再跟随聊天变化。模型支持本地缓存建议、自定义模型与手动输入完整 ID，选择“CLI 默认模型”会交由 CLI 配置决定。修改选项不会发起 AI 请求；每个运行任务只锁定自身控件并保留启动参数，其他 Diff 仍可编辑下一次请求的选项，已完成且代码未变化的解释继续显示。注释使用独立只读请求，不进入聊天历史。
- 侧栏支持手动批量注释，与其他文件的单独注释并行；同一文件不会重复启动请求，队列跳过已有单文件任务和缓存命中的文件，首个错误停止队列。关闭 Diff 或批量窗口后任务继续，重新打开可恢复状态、用时和结果；点击 Diff 的“停止注释”、批量窗口的“停止队列”或 IDE 后台任务的取消，可终止对应请求与 Diff 准备，批量任务同时停止后续文件，保留已完成结果。停止后不会自动继续或重试，关闭项目时会终止所有注释任务。
- 开启 CodeDeck 的“文件上下文”后，在任一 Diff 中选择代码，再切回聊天提问；保留变更前后版本、原始行号和选区原文，统一视图中的跨版本选区分别附带。没有独立的 ChangeList 问答面板。

从独立 ChangeList 插件迁移时，先禁用或卸载旧 **VCS Changelist Sidebar**，再安装 CodeDeck；两者声明为互斥插件，以免重复工具窗和后台监听。旧项目的忽略规则、刷新偏好等沿用原工作区配置；AI 设置统一以 CodeDeck 为准。

### Codex 专属能力

- 通过 `codex app-server --stdio` 使用 Codex 原生 JSON-RPC 协议。
- 支持模型、推理强度、沙箱、审批策略、命令执行审批和结构化提问。
- 支持 Codex Skills、MCP、账户用量和 app-server 专属审批能力。
- 插件 MCP 设置优先显示配置，再读取工具与认证状态；状态读取超时时仍可编辑或停用服务器，并显示“状态待确认”，可稍后刷新重试。启动通知触发的并发刷新会合并处理。
- Codex app-server 具备显式生命周期管理；断线、重启和项目关闭会清理未完成请求。
- Codex 上游连接中断且仍在自动重试时，插件显示“正在重连”并保持当前回合、审批和输入队列；恢复后继续接收回复，重试期间不会提前结束任务。错误提示展示具体原因，最终失败或停止遵循回合状态。

### Claude Code 渠道

- 通过 `claude -p --output-format stream-json` 使用 Claude Code 的结构化流式输出。
- Claude 历史读取当前项目的 Claude Code JSONL 文件，与 Codex 历史分开显示。
- Claude MCP、权限和项目配置仍由 Claude Code CLI 自己管理。
- Claude Code 当前成熟度低于 Codex 渠道，不建议用于不可恢复的关键修改。

## 配置说明

### 本地 CLI 配置

“本地配置”会继续使用 Codex 的 `CODEX_HOME/config.toml`，或 Claude Code 的本机登录与项目配置。CodeDeck 只负责启动 CLI 并展示会话，不替用户保存模型服务账号。

### 自定义 GPT 供应商

自定义 GPT 供应商会通过 Codex `model_providers` 启动覆盖加载，并从 API 基地址下的 `/models` 读取模型。可选择 Responses API 或 Chat Completions API。

### 自定义 Claude 供应商

自定义 Claude 供应商会通过 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 启动 Claude Code，并使用 Bearer 认证从 `/v1/models` 读取模型。

### 提示词与 Agent 身份

全局提示词、共享提示词和 Agent 身份均由用户主动保存。Codex 通过原生 `developerInstructions` 传给新会话，Claude Code 通过 CLI 的附加系统提示传给新会话。

## 已知边界

- Claude Code 渠道仍缺少充分测试，稳定性和兼容性不如 Codex 渠道。
- 自定义供应商的工具调用、模型能力和上下文行为取决于供应商自身兼容性。
- 同一渠道当前只启用一个供应商配置；切换 GPT 供应商会重启 Codex app-server。
- 修改供应商配置后，旧会话不能继续发送，避免把上下文误发到另一个接口。
- Codex 的 Skills、MCP、账户用量、结构化审批与回溯能力来自 app-server；Claude 渠道不具备完全相同的能力面。
- Claude 只对带明确路径的文件工具建立修改基线；纯 Bash/PowerShell 首次写入不会自动进入修改列表。
- 如果 JetBrains Runtime 不提供 JCEF，工具窗会显示不可用提示，需要更换运行时。
- 当前没有 Marketplace 安装包和稳定版发布渠道。
